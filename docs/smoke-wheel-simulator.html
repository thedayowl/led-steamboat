How the smoke works

A burst is three puffs, starting with the one nearest the stack. Each puff starts 0.7 s after the one before. It fades in, holds, then fades out more slowly, and overlaps the next. After the last puff goes out there's a short dark gap, then the burst repeats.

Each farther puff is dimmer. Thinning (fade, 0–255) sets how much dimmer: at 70, each puff loses 27% of full brightness (1.0, 0.73, 0.45), and no puff goes below 10%. The fades follow an S-curve and are squared, which roughly matches how the eye sees LED light, so they look even.

How the wheel works

One spoke set is lit at a time, and the others stay at the unlit level (floor, default 20 of 255) so the spokes never vanish. Every 0.35 s the light moves on to the next set, A → B → C → A. Each set is every third spoke, so each step moves the lit spokes one spoke along (20°) and the wheel seems to turn, counter-clockwise in this drawing.

For the first half of each step the lit set holds steady. For the second half it crossfades into the next one. wheeldir swaps the order to C → B → A without rewiring. Speed scales the clock, so changing it never makes the wheel jump.

The stack and wheel shapes are a sketch. The real strings can be routed any way, and only the group numbers decide the order. The wheel is drawn with 18 spokes of 7 LEDs, every third spoke in the same set (42 LEDs per set; the default table's 20 per set are placeholders to replace when you map the real strings). The other LED counts, colours (smoke FFB060, spokes FF0030, stack and rim FFA040), timing and level maths come from config.h and display.cpp. The screen version is gamma-corrected to look like LED light; real strings are far brighter.
